# История изменений проекта

## 12.02.2026 - Добавление поля description для задач

### Проблема
Задачи создавались без поля `description`, хотя в backend оно было определено как необязательное поле.

### Решение

#### Frontend изменения:

1. **AddTaskForm.jsx**
   - Добавлено поле `description` в `initialState` формы
   - Создан обработчик `handleDescriptionChange` для управления состоянием
   - В `handleSubmit` добавлена отправка `description` (если пустое - отправляется `null`)
   - Добавлен textarea в JSX для ввода описания задачи
   - Удален неиспользуемый импорт `useState`

2. **AddTaskForm.scss**
   - Добавлены стили для `&__textarea`:
     - `resize: vertical` - возможность изменять высоту
     - `min-height: 80px` - минимальная высота
     - `font-family: inherit` - наследование шрифта
     - `line-height: 1.5` - межстрочный интервал

#### Backend
Backend уже корректно обрабатывал `description`:
- В `schemas.py`: `description: Optional[str] = None`
- В `crud.py`: функция `create_task` корректно сохраняет и возвращает description
- В `models.py`: поле `description TEXT` в таблице task

#### UI отображение
TaskList.jsx уже имел логику отображения description в развернутом виде задачи.

### Результат
Теперь при создании задачи можно добавить необязательное описание, которое:
- Сохраняется в базу данных
- Отображается в UI при раскрытии задачи
- Может быть пустым (необязательное поле)


## 12.02.2026 - Разделение пустых состояний в TaskList

### Проблема
При отсутствии задач всегда показывалось сообщение "Задач пока нет", даже когда задачи есть, но не найдены по фильтрам/поиску.

### Решение

#### EmptyState.jsx (новый компонент)
- Создан отдельный компонент для отображения пустых состояний
- Принимает проп `hasAnyTasks` для определения типа сообщения
- Логика:
  - Если `hasAnyTasks === false` → "📝 Задач пока нет" + "Добавьте первую задачу"
  - Если `hasAnyTasks === true` → "🔍 Задачи не найдены" + "Попробуйте изменить параметры"

#### TaskList.jsx
- Добавлен импорт `useTasks` для получения всех задач из базы
- Добавлен импорт компонента `EmptyState`
- Упрощена логика пустого состояния - теперь просто рендерится `<EmptyState hasAnyTasks={allTasks.length > 0} />`

### Результат
- Улучшена читаемость кода через выделение логики в отдельный компонент
- Пользователь видит корректное сообщение в зависимости от ситуации
- Легче поддерживать и расширять функционал пустых состояний
